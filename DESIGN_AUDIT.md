## 2. Factual corrections before implementation

These are wrong in the mockups and must be rendered from real data in the product, because the launch record is reproducibility evidence.

1. **Launch command.** Design shows `hermes run --config … --prompt-file … --workdir … --output-format jsonl`. Real contract: `HERMES_HOME=<trial home> hermes chat --query-file task.txt --oneshot --format stream-json -m <model> --provider <provider> -s <skill> -t <toolsets> --max-turns N --run-budget S --in <workspace> --source tool`.
2. **Config file keys.** Design shows `memory: { enabled: false }`. Real key is `memory.memory_enabled` (and `user_profile_enabled`). Toolsets may be written as a `toolsets` list in config, which matches Hermes' own eval fixtures.
3. **Hermes revision.** Design uses `4c1e9b7`. Pinned revision is `4d04303818b6` (v0.22.4, 21 Oct 2026).
4. **Toolset names.** ConfigForm offers `file, terminal, web, browser, vision, code_execution`. The real list from `hermes tools list` also includes `image_gen, tts, skills, todo, memory, session_search, connections, clarify, delegation, cronjob, computer_use`. The form must load the list from the backend, and `skills` and `memory` being toolsets interacts with the skills and memory configuration fields (spike item).
5. **Memory help text.** ConfigForm says memory defaults off "so repetitions cannot learn from each other". With a fresh home per run, memory cannot carry between runs regardless. The flag only affects behaviour within one run. Reword, and keep the limits doc statement that memory is not an experimented dimension.
6. **Verifier script contract.** Design: `python3 check.py --answer reference.json --fixtures fixtures/`. Flow page: JSON on stdin, one JSON line out. Pick one. Recommendation: CLI args for the paths plus one JSON line on stdout, since it is easier to run by hand.

## 4. Edge cases the design does not draw

Minor, but each needs a decision or a one-line note during implementation.

1. Score status `error` (scorer crashed, judge unreachable) in the inspector. The chip exists and the caption says a banner appears; no artboard shows it. Reuse the ungradable banner with the stack or error text.
2. A scored run that had an earlier failed attempt. The attempt list is drawn only in the execution_error state. Show the attempts table in the header whenever attempts > 1.
3. A/B jump when the counterpart run is cancelled or not yet scored. Hidden while running; define as disabled with reason otherwise.
4. Comparison tab with repetitions = 1. VerdictCard "not computable" is described; the statistics panel variant is not drawn. Render pass rates, no interval, and the sentence from the VerdictCard state.
5. Overview paused by the spend ceiling. The paused chip exists; add a reason line "Paused: spend reached the $2.00 ceiling" with Resume raising the ceiling.
6. No worker connected. Runs would sit queued with no explanation. Add an ErrorBanner on the Overview when zero workers have heartbeated in the last 30 s, naming the Compose service.
7. Unknown model in the price table. Cost columns show "—" and the summary says estimates are unavailable.
8. Uploading a skill whose name already exists. Treat as a new version of that skill, or reject; the dialog does not say. Recommendation: new version, shown in the Version column.
9. Deleting or archiving a configuration. Nothing in the design. Recommendation: no delete in v1; configurations used by experiments are immutable anyway.
10. Multiple candidates in Comparison. The candidate select is described, not drawn. Three-configuration experiments exist in the sample data, so draw nothing extra but implement the select.
11. Breakpoints 1024 to 1279 and below 1024 are described on the visual direction board, not drawn. Acceptable per the brief.
12. Experiment name uniqueness. Not specified. Recommendation: not enforced; ids are the identity.

## 5. Things the design got right that the system design must not lose

- Isolation of "the agent was wrong" (failed) from "the run broke" (error) from "nothing to grade" (ungradable), in colour, pattern and statistics.
- Every count is a link one level down: verdict to grid, grid cell to run, run to tool call.
- Frozen snapshot shown on every experiment view, with versions, hashes and the Hermes revision.
- Invalid tasks shown but not selectable, so run counts change visibly rather than silently.
- Re-score and retry are different verbs with different consequences, and the UI says which.
