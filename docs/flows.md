# Flows A to E: the manual walk

This is the manual check of plan section 16: the flows of the design (the FlowA to FlowD boards, `UI_DESIGN_BRIEF.md`, and Flow E, suite authoring, Phase 5b), walked in a browser against the Compose stack, with real Hermes in real trial containers and the scripted mock model. Nothing calls a real provider and nothing costs money. It takes about 40 minutes, most of it waiting for runs.

Each step says where to go, what to do, and what you should see. The numbers are the ones the walk gave on 26 Oct 2026. The pass rates, differences and verdicts follow from the scripts and repeat exactly; an interval's end can move by one step (1/7 with seven tasks) with another experiment's bootstrap seed. Where a flow needs a real model or a real login, it is adapted, and the step says how.

Two rules for the whole walk:

- **Never press Connect** (Nous Portal) and never start a login. Every configuration here uses provider `custom` with the mock model. With `NOUS_HOST_PROXY` in `.env` and no host proxy running, Nous shows "not running" and the banner's action opens System; with no login at all, the banner offers Connect. Leave both alone.
- Every name you type comes from the setup's `names.txt`, which carries one UTC stamp, so the walk can be repeated.

## Setup

1. Create the walk's files:

   ```bash
   scripts/flows-setup.sh
   ```

   It writes the suite `suites/zz-smoke-flows-<stamp>` (seven tasks: `north`, `south`, `east`, `west`, `open_eur`, `cobalt`, `late_fees`), the skill zip Flow A uploads, and `mock-scripts.json` for the mock, and prints `names.txt`: the suite, the skill zip's path, the three configuration names, the MCP server name and its tools. It calls no API.

2. The sample MCP server in Flow C reads its invoices from `INVOICE_DB_URL`, which Compose gives the worker as `file:///opt/mcp/invoice-db/invoices.csv` unless the shell or `.env` sets it. Make sure neither sets it empty.

3. Start the stack with the mock and its scripts. Compose mounts the file `MOCK_SCRIPTS_FILE` names into the mock and reads the variable from the shell before `.env`, so no file changes. `<out>` is `data/flows-<stamp>` in the repository, a path Docker can mount on Colima and Docker Desktop:

   ```bash
   MOCK_SCRIPTS_FILE=<out>/mock-scripts.json docker compose up -d
   ```

   The worker loads the new suite at start. If the stack was already up, use Suites › Reload all from disk instead.

4. Open http://localhost:8080. The theme toggle is at the top right; check each page in both themes as you go.

What the mock does: without the skill it gets the totals of `north`, `south` and `east` wrong and `west` right; with the skill's phrase in the system prompt it gets every total right. `open_eur` can only be answered from the invoice database, so only the configuration with the MCP server answers it. `cobalt`'s workspace statement is right and the database misses its credit note, so the MCP server makes it wrong. `late_fees` has a `verifier_script` check that Flow D breaks.

Variant, a stalled provider (closer to the board's timeout, less predictable): while an experiment runs, `docker compose pause mock-model` for a few minutes, then `docker compose unpause mock-model`. In-flight runs stop at their deadline (budget + 60 s) as `timeout` and are retried once 30 s later; failed attempts count toward the circuit breaker, so after 14 in a row the experiment fails with "Stopped after 14 failed attempts in a row (timeout)", even when every failed run is still queued for its retry. Retry failed runs then resumes it.

## Flow E: from nothing to a first experiment

## Afterwards

Remove the walk's suites (the suite list then keeps them as "Missing from disk"; experiments, configurations and the MCP server stay, as they have no delete endpoints, and the skill stays because a configuration version names it) and return to the normal configuration:

```bash
rm -rf suites/zz-smoke-flows-<stamp> suites/zz-smoke-flow-e-<stamp>
curl -s -X POST -H 'Content-Type: application/json' -H 'X-Requested-With: flows' \
  --data '{"path":"./suites/zz-smoke-flows-<stamp>"}' http://localhost:3000/api/suites/reload
curl -s -X POST -H 'Content-Type: application/json' -H 'X-Requested-With: flows' \
  --data '{"path":"./suites/zz-smoke-flow-e-<stamp>"}' http://localhost:3000/api/suites/reload
docker compose up -d                                  # from a shell without MOCK_SCRIPTS_FILE: the mock gets ./scripts again
rm -rf data/flows-<stamp>
```
